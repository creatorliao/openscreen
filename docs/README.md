# PARA 工作区说明

本目录采用 [PARA 方法论](https://fortelabs.com/blog/para/) 组织知识资产，分为四个顶层目录。

## 目录用途

### 01-Projects · 项目

存放**有明确起止时间**的子项目、专题任务。

- 每个子项目单独一个文件夹（**需求、方案及同主题配套稿必须进这里**，不要写到 Areas）
- **命名格式**：`R{YYYYMMDD}-{两位序号}-{项目标题}`
  - 示例：`R20250812-01-用户研究专题`
  - 日期为创建日；序号当日递增（01、02…）
- 夹内用编号文件（`00-README` / `01-需求_…` / `02-方案_…`），不要再套一层主题子目录
- 新建夹：`para-structure cp "项目标题"`
- 项目结束或暂停后，整体移至 `04-Archives/`

### 02-Areas · 领域

存放**需要长期持续维护**的内容：规范、制度、职责范围内的文档、反复更新的手册等。

- **禁止**为某一主题再建子文件夹；单文件 `YYYYMMDD-xx-主题.md` 直接落在本目录根下
- 无固定截止日期，但需定期回顾
- 示例：团队编码规范、产品领域知识、运维手册
- 不要把成对的需求/方案写到这里

### 03-Resources · 资源

存放**外部参考资料**：文章剪藏、书单、课件、链接摘要、第三方模板等。

- 来源多为外部，供日后查阅
- 不一定立刻用于当前项目
- **禁止**再建主题子文件夹

### 04-Archives · 归档

存放**已完成、暂停或暂时用不上**的内容（从 Projects / Areas / Resources 迁入）。

- 保持可检索，但不再作为日常活跃工作区
- **禁止**为新主题 mkdir；从 Projects 迁入时保持原项目夹

## 快速操作

在本 PARA 根目录的**上级或仓库根**可使用 CLI：

```bash
para-structure cp "项目标题"     # 在 01-Projects 下新建编号项目目录
para-structure pack docs          # 打包备份
```

## 目录结构一览

```
.
├── 01-Projects/      # 子项目（R日期-序号-标题）
├── 02-Areas/         # 持续维护的规范与领域文档
├── 03-Resources/     # 外部参考资料
└── 04-Archives/      # 已归档内容
```

各空目录含 `.gitkeep`，便于 Git 追踪目录结构。
