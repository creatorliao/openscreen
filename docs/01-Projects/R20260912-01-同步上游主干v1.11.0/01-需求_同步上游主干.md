# 01-需求：同步上游主干到 v1.11.0

**日期**：2026-09-12
**提出**：维护者（口头：「拉取最新的分支」「拉取分支上最新的代码」）
**落点**：`dev-creator`

---

## 一、需求原文与理解

| 原话 | 落到的需求 |
|------|-----------|
| 「拉取最新的分支」 | 先取回远端状态，看清有没有新东西 |
| 「拉取分支上最新的代码」 | 把上游最新代码真正合进当前工作分支 |

**一个前置澄清**：`dev-creator` 的上游是 `fork/dev-creator`（自己的 fork），它当时**没有任何新提交**——本地反而领先 3 个。所以「拉取」在这条线上是空操作，该做的是 **push**。

远端真正有新东西的是 `origin/main`（官方仓）：

```
merge-base(dev-creator, origin/main) = 3957fa24
origin/main 领先 dev-creator：61 个提交
dev-creator 领先 origin/main：6 个提交
新增分支：origin/release/v1.11.0
新增 tag：v1.11.0、v1.11.0-rc.1
```

因此需求收敛为：**把 `origin/main` 合并进 `dev-creator`**。

## 二、为什么必须同步（不同步的代价）

| # | 不同步的后果 | 严重度 |
|---|-------------|-------|
| R1 | **转写/字幕 100% 失败**。资源路径写错，dev 与打包版都 404，报错还是误导人的 `Failed to fetch`（见分析 §三.1） | 🔴 直接打断 G3 |
| R2 | **Windows 播 AV1 片段时进程 0xC0000005 崩溃**（issue #554） | 🔴 直接打断 G1 |
| R3 | Windows 选「Default」麦克风会收到莫名其妙的解析失败警告 | 🟡 体验 |
| R4 | Studio Rec 标签页里麦克风关不掉 | 🟡 体验 |
| R5 | 预览在 VFR seek 后停在错误的一帧 | 🟡 编辑精度 |
| R6 | 基线 `3957fa24` 早已落后，越拖合并面越大、冲突越难解 | ⚪ 工程债 |
| R7 | 后续要出的安装包会带着上面全部缺陷 | 🔴 发布风险 |

## 四、验收口径

| # | 验收项 | 判据 |
|---|--------|------|
| A1 | 合并完成 | `origin/main` 是 `dev-creator` 的祖先；`git rev-list --count dev-creator..origin/main` = 0 |
| A2 | 无冲突残留 | 全仓无 `<<<<<<<` / `>>>>>>>` |
| A3 | 在途工作无损 | 工作区改动与合并前备份 patch 内容逐行一致 |
| A4 | 本地定制保留 | `build:win:portable` 仍在；`AGENTS.md` 重写版仍在，且吸收上游修正 |
| A5 | 版本号正确 | `package.json` / `package-lock.json` 三方一致为 `1.11.0` |
| A6 | 静态健康 | `npx tsc --noEmit`、`npx tsc -p tsconfig.test.json --noEmit` 无输出 |
| A7 | 单测全绿 | `npm run test` 全通过 |
| A8 | 翻译完整 | `npm run i18n:check` PASSED |
| A9 | **原生二进制是否最新** | 用「标记串 + 控制串」双探测证明，不能只看文件时间 |
| A10 | 应用实跑 | 原生改动必须走 manual e2e —— **本次未做，见 09-执行留痕 §五** |
