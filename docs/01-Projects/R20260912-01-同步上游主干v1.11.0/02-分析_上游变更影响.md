## 二、新功能：只有 1 个

### 录制后自动缩放（cursor-dwell auto-zoom）

把**旧编辑器**已有的「录制后自动给光标停留处加缩放」补进新编辑器链路。此前新引擎导入一条新录屏只种一个 clip，不生成缩放，用户必须手点魔棒。

| 提交 | 作用 |
|------|------|

## 六、⚠️ 核心发现：本地原生二进制落后于源码

这是本次分析最有价值的结论——**决定了能不能直接出安装包**。按 AGENTS.md 的方法实测（Git Bash 没有 `strings`，用 `grep -a` 替代）：

### `compositor_view.node`（mtime `9月8 05:59`）

| 串 | 类型 | 结果 |
|---|---|---|
| `decode_frame_n only supports H.264 D3D11VA` | 标记（基线无、现在有） | **ABSENT** |
| `C0 D3D11VA only supports H.264` | 标记 | **ABSENT** |
| `no decoder for codec_id` | 标记 | **ABSENT** |
| `aucun clip à exporter` | 控制 | HIT |
| `[pipeline] encodeur vidéo` | 控制 | HIT |
| `aucun encodeur vidéo utilisable sur cette machine` | 控制 | HIT |

控制串全 HIT ⇒ 检索方法有效 ⇒ 标记串 ABSENT 是**真缺失**。**AV1 那 1400 行修复不在本地 addon 里。**

### `wgc-capture.exe`（mtime `9月8 00:13`）

该修复（`42d15e67`，**2026-09-10**）没有引入新字符串，故用日期判定：**二进制早于提交 ⇒ 不包含该修复**。

### 一个方法论坑（值得记下）

最初挑的标记串是 `AV1 clip must use CpuFrames`、`AV1 on Hardware must use CpuFrames, not D3D11VA`、`attach observer was not installed`。它们探测结果同样是 ABSENT —— 但结论**碰巧正确而推理无效**：这几个串位于 `#[cfg(test)] mod tests`（`pipeline_windows.rs` 第 1807 行起），**任何 release 构建都不会有**。

> **规则**：挑标记串必须先确认它落在**生产代码路径**（行号小于 `mod tests` 起止），否则「ABSENT」既可能因为二进制旧，也可能因为这段根本不进 release 构建。

## 七、结论

1. 这 61 个提交**必须合**——里面有 G3 的救命修复（转写全废）和 G1 的崩溃修复（AV1）。
2. 合并本身低风险：冲突仅 3 处且成因单一，依赖零变化。
3. 真正的风险**不在合并，在原生**：源码已前进 2331 行原生代码，而本地二进制停在 9月8。**不重编原生，任何验证和出包都是在测旧代码路径。**
