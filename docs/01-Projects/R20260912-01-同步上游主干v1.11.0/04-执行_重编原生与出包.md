## 六、执行中遇到的两个阻塞与解法

### 1. electron-builder 打包超时 `ETIMEDOUT 20.205.243.166:443`

首次 `npx electron-builder --win` 直接失败。原因是**只启动了 Shadowsocks、没有 export `HTTPS_PROXY`** —— electron-builder 用 `got` 下载 `electron` zip / `nsis-3.0.4.1.7z` / `nsis-resources-3.4.1.7z`，走的是 GitHub。

```
⨯ connect ETIMEDOUT 20.205.243.166:443
```

**解法**：`export HTTPS_PROXY=http://localhost:1087`（`HTTP_PROXY` 一并设）后重跑，三个下载均 `progress=100%`。

> 与 `docs/02-Areas/win-build-env-setup.md` 记的一致：代理必须**在构建前**起好并 export，否则表现为随机超时而非明确报错。

### 2. portable 改名 `EPERM: operation not permitted`

`scripts/build-windows-portable.mjs` 的收尾动作 `rename(win-unpacked → openscreen-portable-1.11.0)` 报 `EPERM`（`errno -4048`）。

**排查**：目标目录不存在（脚本已先清理），`win-unpacked` 内容完整，非权限问题。属 Windows 上典型的**文件句柄未释放**（刚写完 200+ MB 目录，Defender 正在扫描，或 electron-builder 子进程句柄尚未回收）。

**解法**：不重跑整个打包（那要几分钟），只重试那一句 rename —— **第 1 次就成功**。随后手工 `rm -rf release/.portable-staging` 补完脚本第 4 步。

> **建议**：这一句可以加固为「带退避的重试」，否则在真实机器上会随机出现、且提示信息（`operation not permitted`）指向错误方向。

---

### 3. ⚠️ 自己踩的坑：`npx asar extract-file` 把源 `package.json` 覆写了

**现象**：出包后的验证扫尾，发现仓库根 `package.json` 被改写——`scripts` 63 条全没、`devDependencies` 28 条全没、`contributors` 没了、缩进从 tab 变 2 空格。mtime 恰好是验证那一刻，看起来像构建链路把源文件写坏了。

**误判方向**：先怀疑 electron-builder 的 `fileTransformer`（它就是干这个剪枝的）。读 `node_modules/app-builder-lib/out/fileTransformer.js` 后排除：`modifyMainPackageJson()` **只读不写**，只是 `return` 剪枝后的字符串给文件复制器写入**输出目录**。

**真因**：一条验证命令写错了。

```bash
# 错：asar extract-file 没有输出路径参数
npx asar extract-file "$P/resources/app.asar" package.json /dev/stdout
```

```
Commands:
  extract-file|ef <archive> <filename>   extract one file from archive
```

没有输出路径——**它把文件按 basename 写到当前目录**。多余的 `/dev/stdout` 被当作无关参数忽略，于是 in-asar 里那份剪枝过的 `package.json` 直接盖到了仓库根。四项特征（无 scripts / 无 devDeps / 无 contributors / 2 空格缩进）与 `cleanupPackageJson()` 的输出完全吸合，闭环。

**修复**：`git checkout -- package.json`，改验（63 scripts / 28 devDeps / 43 deps / contributors 均在）。

**教训（已写回工作流）**：
- 要**读** asar 里的文件，用 API 而不是 CLI：`node -e "require('@electron/asar').extractFile(archive, name)"` —— 它 `return` Buffer，不落盘。
- 任何“为了看一眼”而跑的 CLI，先看它的参数签名：`extract-file` 这种以 basename 落盘的子命令，**CWD 就是靶子**。
- 幸而 `package.json` 受版本控制且当时未提交，`git checkout --` 就回来了；同名操作如果砸的是未跟踪文件（如 `electron/logging/`），损失不可逆。
- 这也说明 **`git status` 在构建后必看**：一个本应在列表之外的 `M package.json`，就是最早、最便宜的告警。
